# Analysis
The idea is clear: 

Greedy Algorithm for interval scheduling: sorting by right endpoint (second value) in ascending order and then greedily selecting, the longest chain of pairs can be obtained in `O(N logN)` time.

I review a point that maybe easily ommited:

You can sort the original `pairs[]` by right value: 
```cpp
        // 1. Greedy strategy: Sort pairs by their right value (end point) in ascending order
        std::sort(pairs.begin(), pairs.end(),
                  [](const std::vector<int>& a, const std::vector<int>& b) {
                      return a[1] < b[1];
                  });
```

but you cann't do it by left value: 
```cpp
        std::sort(pairs.begin(), pairs.end(),
                  [](const std::vector<int>& a, const std::vector<int>& b) {
                      return a[0] < b[0];
                  });
```

Because it will influent the next step: greedily choice: 

This relates to the core greedy strategy of the **Interval Scheduling Problem**: sorting by the right endpoint essentially aims to **"leave as much space as possible for subsequent pairs."**

1. Core Intuition: Why Focus on the Right Endpoint?

    In this problem, when we append a subsequent pair $[c, d]$, its left endpoint must be strictly greater than the right endpoint of the previous pair (i.e., $c > b$).

    Suppose we have two choices for the next pair:
    - **Pair A**: `[1, 10]` (right endpoint is 10)
    - **Pair B**: `[2, 3]` (right endpoint is 3)

    Obviously, choosing **Pair B** is far superior to choosing **Pair A**! Because Pair B's right endpoint is very small (only 3), any pair starting from 4 onwards has a chance to be chained next. However, if we choose Pair A, the right endpoint extends all the way to 10, wasting all candidate pairs before 10.

    > **Greedy-Choice Property**: At each step, choosing the pair that finishes earliest (smallest right endpoint) and is compatible with the previous choice preserves the maximum degree of freedom (largest remaining interval) for subsequent chaining.

2. What Happens If We "Sort by Left Endpoint"? (Counterexample Analysis)

    Suppose we sort by left endpoint in ascending order:
    `pairs = [[1, 100], [2, 3], [4, 5]]`

    - **After sorting by left endpoint**: `[[1, 100], [2, 3], [4, 5]]` (order remains unchanged).
    - **Greedy Traversal**:
      - Encounter `[1, 100]`: Select it; current right endpoint updates to 100.
      - Encounter `[2, 3]`: Since $2 < 100$, it cannot be chained.
      - Encounter `[4, 5]`: Since $4 < 100$, it cannot be chained.
      - **Final Result**: `1` (only `[1, 100]` was selected).

    However, the optimal solution is clearly selecting `[2, 3] -> [4, 5]`, giving a maximum chain length of **2**.

    **Root Cause**: When sorting by left endpoint, earlier pairs may contain an extremely large right endpoint. Once selected, such a pair completely overlaps and invalidates many shorter, chainable intervals that follow.

3. One word to summary
    > "Greedy algorithm should be greedy!" - "贪心算法要够贪(bushi)"

Comparison: 

| Problem Type | Common Sorting Rule | Objective / Rationale |
| :--- | :--- | :--- |
| **Maximum Length of Pair Chain / Non-overlapping Intervals (LC 646 / LC 435)** | **Ascending by Right Endpoint** | **Greedy Strategy**: Finish the current interval as early as possible to leave maximum space for subsequent intervals. |
| **Russian Doll Envelopes / Longest Increasing Subsequence (LC 354)** | **Ascending by Left Endpoint, Descending by Right Endpoint** | **Dimension Reduction**: Transform 2D inclusion into 1D Longest Increasing Subsequence (LIS) Dynamic Programming. |
| **Merge Intervals (LC 56)** | **Ascending by Left Endpoint** | **Coverage & Merging**: Process continuity from left to right, checking whether the current interval's left endpoint can be covered by the previous interval. |

# Code

```cpp
class Solution {
public:
    /**
     * @brief Find the maximum length of pair chain that can be formed
     *
     * @param pairs Reference to a 2D vector where pairs[i] = [left, right]
     * @return int The maximum length of the pair chain
     */
    int findLongestChain(std::vector<std::vector<int>>& pairs) {
        if (pairs.empty()) {
            return 0;
        }

        // 1. Greedy strategy: Sort pairs by their right value (end point) in ascending order
        std::sort(pairs.begin(), pairs.end(),
                  [](const std::vector<int>& a, const std::vector<int>& b) {
                      return a[1] < b[1];
                  });

        // 2. Traversal and greedy choice
        int count = 0;
        int curr_end = INT_MIN;

        for (const auto& pair : pairs) {
            if (curr_end < pair[0]) {
                curr_end = pair[1];
                count++;
            }
        }

        return count;
    }
};
```
